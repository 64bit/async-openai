fix(responses): make OutputMessage.id optional

The OpenAI Responses API sometimes omits the `id` field on output_text
items when they appear in the input array (e.g. multi-turn conversations
passing assistant messages back). Previously `OutputMessage.id` was
`String` (required), causing deserialization failures.

Changed to `Option<String>` with `#[serde(default, skip_serializing_if =
"Option::is_none")]` — same pattern already used by `ReasoningItem.id`
(PR #535).

Fixes #565
